## Что изменено после ошибки пользователя

В 0.6 chat smoke подменял запрос renderer через page.route и не доказывал связь с OpenRouter. Renderer-fetch ошибки скрывались общим сообщением и повторялись четыре раза. Причина на компьютере пользователя (CORS, DNS, прокси или иной сбой) по такому сообщению не установлена.

В 0.6.1 чат/каталог portable переведены на owner-only IPC → Electron net.fetch. Два фиксированных HTTPS endpoint, никаких произвольных URL/редиректов/платных маршрутов; тело пересобирается по whitelist, цены проверяются повторно. TLS/sandbox/CORS-защита не отключается. Виджет/подфрейм/чужой renderer не могут вызвать запрос или отмену.

Проверены: коды DNS/TLS/PROXY/OFFLINE/CONNECTION без сырых ошибок, сохранение HTTP статуса, пустые/некорректные ключи, платные модели, цена, размеры сообщений/ответов, лимит активных операций, отмена/таймаут/shutdown, отсутствие прямого renderer-fetch в native ветке, отсутствие ключа в запросе каталога. Ошибка соединения останавливает перебор, черновик сохраняется. HTTP-ошибки отдельных моделей и таймауты по-прежнему допускают ограниченный free-only fallback.

## Обязательные проверки Windows до публикации — все пройдены

- Реальный публичный OpenRouter каталог через IPC из packaged EXE: HTTP 200.
- Реальный POST с заведомо неверным тестовым ключом: HTTP 401. Действующих ключей/платных запросов нет.
- Затем native mock-чата, DPAPI/key reload, виджет/восстановление и запуск самого portable EXE.
- Настоящий синтез WAV Piper/Denis.

**Каталог и 401 проверяют только сетевой путь, не генерацию ответа с действующим ключом.** Результат на CI не гарантирует доступность API из сети пользователя. Его ключ/переписка не использовались. Реальный микрофон, прослушивание и GPU/DPI/многомониторный QA остаются ручными. Courtney/Earl, фонемная артикуляция и цифровая подпись не готовы.
